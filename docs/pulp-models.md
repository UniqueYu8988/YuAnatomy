# 髓腔示意模型

## 目的与边界

修复旧生成器的全局轴错位、圆柱髓室、预设根管曲线穿出真实牙体的问题。保留已有 28 颗牙的外部几何与 ID，提供与各自外表面匹配的连续内部曲面。

这不是牙髓组织或真实管腔的分割。外形不能唯一确定髓角、MB2、峡部、C 形根管、侧支、根尖孔和年龄性变化。示意中的分支由外部牙根形态推算，不承诺与资料中的根管数一致。不能用于诊断、操作路径或工作长度测量。

## 数据流程

1. 直接读取 `public/head-neck/atlas.json` 指向的 float32 顶点及 uint32 三角形，记录源几何 SHA-256；先要求牙体表面封闭。
2. 以包围盒中心作为存储原点，以 PCA 求每颗牙的局部长轴，并根据上下颌确定冠根方向。PCA 仅是几何辅助轴，不声称识别了真实牙颈线。
3. 在局部坐标系中建立 0.12 mm 体素，逐层计算牙体截面的内部距离。冠部以截面的局部主轴和内部加权中心约束椭圆包络，形成两端平滑过渡的髓室示意，避免平截圆柱。
4. 在根部多个高度分离外部牙根对应的内部区域，寻找各区域根尖侧可用的内部端点。从髓室到各端点，用内部距离加权的最短路径求走向，平滑并密集重采样；沿路径生成连续渐细的管腔，再与髓室合为一张曲面。路径不得经过牙体外部。几何根分支不等于实际根管数；融合根与内部变异不能由此方法识别。过小孤立体素可删除，删除体积有上限。
5. 平滑隐式场并限制在牙体内部，提取一张连续封闭曲面。平滑和 float32 量化后再进行验证；不使用渲染遮挡掩盖穿模。
6. 输出 `public/pulp/atlas.json` 和带内容哈希的二进制资源。顶点单位仍为米、相对牙体包围盒中心；场景中与牙体共用中心与拆解位移。

体素尺寸不是扫描精度。0.30 mm 内部计算余量和代码中的管径/冠根比例均为示意生成参数，不是牙本质厚度或临床尺寸标准；该方法的封闭末端也不代表正常根尖孔。分辨率不足的细小结构不会被臆造出来。

## 重建

浏览软件不需要 Python；已生成的静态数据随项目交付。只有修改生成算法或牙体资源时需要：

```powershell
python -m pip install --target work/pulp-runtime -r scripts/pulp-requirements.txt
python scripts/build-pulp.py
npm run check
npm run validate
npm run build
```

单牙开发可运行 `python scripts/build-pulp.py --only FJ1254`，仅输出至 `work/pulp-preview`，不会发布不完整的全牙列资源。生成缓存放在 `work/pulp-cache`，按脚本和源几何的哈希隔离。整个批次验证成功后才写入正式清单。

## 验证原理

生成端使用 trimesh 验证真实牙体表面；`npm run validate` 使用独立的 JavaScript BVH 距离与射线算法重新计算，不信任生成器记录的通过标记。

对每个髓腔三角形，计算其质心到牙体表面的最近距离 d，以及质心到三个顶点的最大距离 r。要求 d-r > 0.025 mm；整片三角形位于半径 r 的球内，因此不能在顶点之间穿越牙体表面。结合内部起点射线检查、封闭且一致的边绕序和全网格连通检查，防止整片错位、面间穿模、开裂及游离片段。

同时检查资源长度、源/目标哈希与坐标配对，并用整体移出牙体、过大三角形和删除表面三种负例确认检查确实能失败。这是保守的几何证书，不是医学审校。

## 后续升级

获得允许再分发的同标本牙体与髓腔分割后，可增加真实标本视窗，使用同一套变换加载内外结构。记录标本牙位、来源链接、许可、扫描/分割参数与审校状态。不要用通用生成模型补造内部“真实细节”，也不要将教材中的典型根管数硬塞进不匹配的牙根。
